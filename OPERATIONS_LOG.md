# 🧭 Рабочий журнал агента (RUNBOOK / SOP)

Этот документ — мой «мозг» при работе с проектом «фото + голос → видео».
Когда возникает задача или ошибка, я действую **строго по этому журналу**:
определяю место обработки, сам выбираю технические параметры (разрешение,
качество, offload и т.д.), запускаю, а при сбое — разбираюсь по чек-листу ниже.

---

## 1. Что за система и где она живёт

| Компонент | Файл | Назначение |
|-----------|------|-----------|
| Ядро генерации | `ltx2/agent.py` | собирает команду LTX-2 A2Vid (фото→видео) |
| Озвучка | `ltx2/tts.py` | Silero TTS (текст→речь) / XTTS (клон голоса) |
| CLI | `ltx2_agent.py` | запуск из терминала |
| Веб-форма | `webui/` | HTML-форма + сервер, запуск из браузера |
| Запуск сервера | `run_webui.py` / `run_webui.bat` | из любой папки / Windows |
| Установка | `setup_ltx2.sh` | ставит LTX-2 + скачивает веса |

**Поток данных:** фото + текст/аудио → озвучка (Silero) → LTX-2 A2Vid
(фото = кадр 0, аудио = драйвер) → видео `*.mp4` в выходную папку.

## 2. ГЛАВНЫЙ РАЗДЕЛ: где происходит обработка?

**LTX-2 — это 22-миллиардная модель. Она требует GPU (NVIDIA, CUDA) и скачанных
весов на десятки ГБ.** Это определяет всё остальное.

### Как я решаю «где обрабатывать» — чек-лист среды

Запускаю `python ltx2_agent.py --check-env` или проверяю вручную:

```bash
nvidia-smi          # есть ли видеокарта
python -c "import torch; print(torch.cuda.is_available())"
free -h             # сколько ОЗУ
nproc               # сколько ядер CPU
df -h /             # место на диске
python -c "import ltx_pipelines"   # установлен ли LTX-2
ls models/ltx-2.3   # есть ли веса
```

### Три сценария и мой выбор параметров

**A) Есть GPU + веса (реальный ПК пользователя) → обрабатываю локально.**
- **Разрешение по умолчанию — 720p** (для всех форматов). Пользователь выбирает
  из готовых уровней: `720p` (рекомендуется), `1080p`, `4K` — каждое отображается
  на валидные для LTX-2 размеры (кратны 64) автоматически.
- Маппинг 720p (по умолчанию): portrait `576×1024`, landscape `1024×576`, square `704×704`.
- Автовыбор по VRAM (если 720p не влезает):
  - VRAM ≥ 24 ГБ → можно `1080p`/`4K`.
  - VRAM 12–24 ГБ → 720p, при нехватке добавить `--offload cpu`.
  - VRAM < 12 ГБ → 720p + `--offload cpu`/`disk` + `--quantization fp8-cast`.
- Качество/скорость: `--quantization fp8-cast` когда памяти мало;
  `--offload cpu` когда ОЗУ много, а VRAM мало.

**B) Нет GPU / нет весов (текущая онлайн-песочница Arena) → обработать ЗДЕСЬ НЕЛЬЗЯ.**
- Не запускаю безнадёжную генерацию. Сразу сообщаю пользователю честно:
  «здесь видео собрать невозможно — нужен ваш ПК с GPU».
- Единственное, что делаю в песочнице: собираю **озвучку** (Silero на CPU),
  генерирую/проверяю **команду** (`--dry-run`), проверяю логику, пишу код.
- Если пользователь ждёт готовое видео прямо из песочницы — **не обещаю**, а
  предлагаю: (1) запустить на своём ПК, либо (2) переключиться на облачный API
  (с ключом) — тогда видео придёт по ссылке.

**C) Нет GPU, но пользователь хочет «просто ссылку» → нужен облачный сервис.**
- Переключаю на сервис с API-ключом (например, HeyGen — уже есть в репозитории
  `heygen_client.py`, или бесплатный облачный эндпоинт). Тогда результат —
  URL видео, и он работает из любого места без своей видеокарты.

## 3. Автовыбор параметров (мои решения по умолчанию)

| Параметр | Моё решение | Почему |
|----------|-------------|--------|
| Длительность | 15 сек (запрос пользователя) | по умолчанию в задаче |
| Соотношение сторон | `portrait` (9:16), если пользователь не сказал | тренд — вертикальные ролики |
| Разрешение | **720p** (по умолчанию), затем 1080p/4K | баланс качество/память |
| fps | 24 | стандарт, 8k+1 кадров |
| Озвучка | Silero, женский голос `kseniya`/`baya` | если текст, без аудио |
| Голос пользователя | клон (XTTS) если дал образец + просит | только по явному запросу |
| offload / quantization | включаю при нехватке VRAM | иначе не запустится |
| seed | 42 | воспроизводимость |

**Правило:** не спрашиваю пользователя о технических деталях, которых он не
понимает. Беру решение сам, но при большом потреблении ресурсов предупреждаю.
В веб-форме **все технические поля — выпадающие списки с готовыми вариантами**
(длительность, аспект, разрешение, fps, offload, квантование, сила привязки,
голос), без ручного ввода чисел.

## 4. Запуск (после того как среда позволяет)

```bash
# из папки проекта:
python ltx2_agent.py --photo me.jpg --text "Я родилась 05 февраля 1987 года и я красотка"

# с настройками (я сам подбираю под GPU):
python ltx2_agent.py --photo me.jpg --audio voice.wav \
  --aspect portrait --duration 15 \
  --offload cpu --quantization fp8-cast      # если VRAM мало

# просто показать команду, не запуская:
python ltx2_agent.py --photo me.jpg --audio voice.wav --dry-run
```

Веб-форма: `run_webui.py` (или двойной клик `run_webui.bat`) → `http://localhost:8001`.

## 5. ЧТО ДЕЛАТЬ ПРИ ОШИБКЕ (главный чек-лист разбора)

Когда приходит «ОШИБКА: LTX-2 завершился с кодом 1» или любая другая:

1. **НЕ пугаюсь сухого кода.** «код 1» — это просто «упало», а не причина.
2. **Смотрю настоящую причину:**
   - читаю `detail` в ответе (я его уже добавляю в `ltx2/agent.py`);
   - запускаю команду вручную с `--dry-run` и вижу точную команду;
   - смотрю stderr процесса.
3. **Проверяю среду по п.2** (GPU? веса? torch? ltx_pipelines?).
4. **Сопоставляю с типовыми ошибками (таблица ниже)** и применяю фикс.
5. **Если дело не в моём коде** (не хватает ресурсов / нет модели) —
   честно говорю пользователю и предлагаю рабочую альтернативу, не «чиню»
   вручную то, что невозможно.

## 6. Таблица типовых ошибок и решений

| Симптом | Причина | Моё действие |
|---------|---------|--------------|
| `ModuleNotFoundError: No module named 'ltx_pipelines'` | LTX-2 не установлен | запустить `setup_ltx2.sh` |
| `ModuleNotFoundError: No module named 'webui'` | запуск не из папки проекта | использовать `run_webui.py` / `.bat` |
| `No such file or directory` (пути моделей) | веса не скачаны | скачать (см. setup), проверить env-переменные LTX2_* |
| `CUDA out of memory` / «OOM» | не хватает VRAM | снизить разрешение, включить `--offload cpu`/`disk`, `--quantization fp8-cast` |
| `no GPU / cuda unavailable` | нет видеокарты | сообщить: обрабатывать негде; предложить ПК или облако |
| `address already in use` (8001) | сервер уже запущен | не запускать второй; использовать тот, что работает |
| Пусто/битый mp4 на выходе | генерация прервалась | проверить лог, повторить с меньшим разрешением |
| Озвучка тихая/нет звука | аудио не подхватилось | проверить `--audio-path`, что wav создан |

## 7. Принципы моей работы (не нарушать)

1. **Честность вместо обещаний.** Если что-то невыполнимо в текущей среде —
   говорю прямо и даю реальный путь (локально или облако). Не имитирую успех.
2. **Не дёргаю пользователя техническими деталями.** Решения по разрешению,
   offload, голосу и т.п. принимаю сам, обоснованно.
3. **Всё воспроизводимо.** Команды логируются, пути настраиваются env-переменными.
4. **Работаю на машине, где реально есть ресурсы** (ПК пользователя), а
   песочницу использую для кода, тестов и озвучки.
5. **Если нужен результат «по ссылке» из облака** — честно спрашиваю, готов ли
   пользователь дать API-ключ сервиса (HeyGen и т.п.), и подключаю его.
