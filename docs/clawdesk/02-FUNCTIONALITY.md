# 02 · Функциональность ClawDesk

Легенда приоритетов: **P0** — без этого продукта нет (MVP), **P1** — нужно к публичной бете,
**P2** — после.

## Модуль 1. Мессенджер

| # | Функция | Приоритет | Описание |
|---|---|---|---|
| 1.1 | Список чатов = штат | P0 | Боты как контакты: аватар, роль, статус присутствия, счётчик непрочитанного |
| 1.2 | DM с ботом | P0 | Обычный диалог, история, вложения, markdown, код |
| 1.3 | Групповые чаты | P1 | Несколько ботов + человек, обращение по `@имя`, общий контекст треда |
| 1.4 | Треды-задачи | P0 | Любое сообщение может стать задачей; тред показывает шаги, статус, стоимость |
| 1.5 | Инлайн-аппрувы | P0 | Карточка с кнопками прямо в треде |
| 1.6 | «Показать работу» | P0 | Таймлайн скриншотов и действий по шагу/задаче |
| 1.7 | Присутствие | P1 | 🟢 работает / 🟡 ждёт тебя / ⚪ спит / 🔴 ошибка — из реального состояния сессии |
| 1.8 | Поиск | P1 | По сообщениям, задачам, артефактам |
| 1.9 | Мобильный доступ | P0 | Через Telegram-канал OpenClaw (быстрый путь) + iOS node позже |
| 1.10 | Уведомления | P1 | Только на аппрувы, блокировки и завершение задач; тихий режим по расписанию |
| 1.11 | Черновик отчёта | P2 | Бот показывает предварительный ответ и правится по комментариям в треде |

**Приёмка 1.4:** из сообщения «собери расходы за Q2» в треде появляется задача с планом,
статусом, счётчиком шагов и итоговой стоимостью; тред переживает перезапуск gateway.

## Модуль 2. Боты (штат)

| # | Функция | Приоритет | Описание |
|---|---|---|---|
| 2.1 | Нанять бота | P0 | Мастер: имя, роль, шаблон, модель, профиль инструментов |

| 2.5 | Свой компьютер | P0 | Контейнер и браузерный профиль на бота, видно статус и потребление |

аккаунтами; куки не пересекаются; `docker inspect` показывает разные контейнеры и тома.

## Модуль 3. Доступы к сервисам

| # | Функция | Приоритет | Описание |
|---|---|---|---|
| 3.1 | Ручной логин | P0 | Открывается окно браузера бота, человек входит сам, сессия сохраняется в профиль |
| 3.2 | API-ключи | P0 | Хранение через SecretRef, никогда не в контексте модели |
| 3.3 | OAuth-коннекторы | P1 | Google, Microsoft, Notion, Slack, HubSpot — где есть нормальный OAuth |
| 3.4 | Здоровье сессий | P1 | Периодическая проверка «залогинен ли»; протух → карточка «нужен вход» |
| 3.5 | Детект капчи/2FA | P0 | Обнаружил → останавливается и зовёт человека, не пытается обойти |
| 3.6 | Приоритет API | P1 | Если у сервиса есть API — по умолчанию используем его, UI как фолбэк |
| 3.7 | Egress-allowlist | P1 | Бот ходит только на домены своих сервисов |

**Приёмка 3.5:** на странице с капчей бот не делает попыток решения, шлёт в тред скриншот
и сообщение «нужен человек», задача переходит в `blocked`.

## Модуль 4. Задачи и надёжность («от 90% к 100%»)

| # | Функция | Приоритет | Описание |
|---|---|---|---|
| 4.1 | План перед действием | P0 | Бот формулирует шаги и критерии приёмки до старта |
| 4.2 | Definition of Done | P0 | Хранится в задаче, проверяется автоматически на шаге verifying |
| 4.3 | Шаг verifying | P0 | Независимая перепроверка результата; без неё нельзя `done` |
| 4.4 | Ретраи с разбором | P0 | До 3 попыток, каждая с записанной причиной провала и изменённым подходом |
| 4.5 | Блокировка вместо догадки | P0 | Не хватает данных/прав → `blocked` + конкретный вопрос человеку |
| 4.6 | Бюджеты | P1 | Лимит токенов/денег/времени на задачу; исчерпан → `blocked` |
| 4.7 | Дерево подзадач | P1 | Декомпозиция через sub-агентов, статус детей в родительском треде |
| 4.8 | Очередь и приоритеты | P2 | Порядок работы бота, срочные вне очереди |
| 4.9 | Ежедневная сводка | P1 | Утром: что сделано, что ждёт аппрува, что заблокировано, сколько потрачено |
| 4.10 | Отмена | P0 | Стоп задачи с корректным завершением контейнеров и вкладок |

**Приёмка 4.3:** бот, создавший счёт в CRM, обязан перечитать созданную запись
и приложить её id и скриншот; при несовпадении суммы задача не закрывается.

## Скоуп MVP (что должно работать в первой демонстрируемой версии)

1. Мессенджер с DM, тредами-задачами и инлайн-аппрувами (1.1–1.6).
2. Найм бота с профилем инструментов и собственным контейнером (2.1, 2.4, 2.5, 2.7).
3. Ручной логин в сервис и сохранение сессии (3.1, 3.2, 3.5).
4. Задачи с планом, DoD, verifying, ретраями и блокировками (4.1–4.5, 4.10).
5. Политика аппрувов и карточка решения (5.1–5.3, 5.7).
6. Обучение рутины текстом + пробный прогон + cron (6.1, 6.4, 6.7).
7. Аудит со скриншотами и «показать работу» (8.1, 8.2).
8. Стоимость задачи в треде (9.1, 9.3).
9. Установка и онбординг (10.1, 10.2).

**Демо-сценарий приёмки MVP** (должен проходиться целиком, без правки кода):

> Установить стек. Нанять бота «Алиса · финансы» с профилем `operator`.
> Залогинить её вручную в тестовый Notion и тестовый почтовый ящик.
> Написать: «Каждый понедельник в 10:00 собирай из почты счета за неделю,
> заноси в базу Notion «Расходы» и присылай мне сводку. Платежи не проводи без меня.»
> Бот выдаёт план и DoD → пробный прогон → находит 3 счёта → заносит → на шаге
> «оплатить» запрашивает аппрув → человек отклоняет один и одобряет два →
> бот проверяет созданные записи → присылает сводку со стоимостью $0.14 →
> рутина встаёт в расписание. В «Показать работу» видны 12 скриншотов.
