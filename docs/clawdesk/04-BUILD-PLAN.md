# 04 · План работ

Оценки даны в человеко-неделях для команды из 3 инженеров (1 фулстек-фронт,
1 бэкенд/инфра, 1 агентный инженер) + продакт на полставки.

## Спринт 1 · Каркас (2 недели)

| Задача | Кто | Оценка |
|---|---|---|
| Монорепозиторий, CI, линтеры, docker-compose | бэк | 3 д |
| `packages/gateway-client` (WS, реконнект, идемпотентность) | бэк | 4 д |
| Управление `openclaw.json` (валидация, hot-reload, версионирование) | бэк | 2 д |
| Скелет мессенджера: сайдбар, чат, WS-стрим ответов | фронт | 6 д |
| Реестр ботов: схема, CRUD API, компилятор BotSpec | агент | 5 д |
| Провижининг контейнера и Chrome-профиля на бота | бэк | 4 д |

**DoD спринта:** можно нанять бота из UI, написать ему в чат и получить ответ;
бот живёт в своём контейнере.

## Definition of Done (общий, для любой задачи)

1. Код + типы + тесты (unit на логику, интеграционный на поток).
2. Демо-сценарий проходит целиком после изменения.
3. Нет секретов в логах (автотест на паттерны ключей).
4. Обновлены `CHANGELOG.md` и релевантный раздел документации.
5. Ядро OpenClaw не форкнуто; отличия — только конфиг/плагины/скиллы.

## Метрики, которые смотрим еженедельно

| Метрика | Цель к концу спринта 6 |
|---|---|
| TTFV (установка → первая задача) | ≤ 20 мин |
| Доля задач `done` без вмешательства на обученных рутинах | ≥ 70% |
| Аппрувов на задачу | ≤ 1.5 |
| Медианная стоимость задачи | ≤ $0.20 |
| Флаки рутин (провал из-за UI) | ≤ 10% прогонов |
| Время пробуждения замороженного бота | ≤ 3 с |
| Утечек секретов | 0 |

## Риск-контрольные точки

- **Конец спринта 3:** если ручной логин + аппрувы не дают ощущения безопасности
  у пилотного клиента — пересматриваем модель доступов (в сторону API-first).
- **Конец спринта 4:** если «покажи один раз» даёт < 3 успешных прогонов из 5 —
  смещаем акцент на обучение текстом + библиотеку готовых рутин, рекордер уводим в P2.
- **Конец спринта 6:** если себестоимость активного пользователя > $12 —
  поднимаем цену Pro или ужесточаем idle-freeze и дефолтную модель.
