# 🤖 Telegram-бот с настройкой этапов (веб-панель + Telegram-панель)

Бот для «прогрева» клиентов: после нажатия **/start** он по очереди отправляет
клиенту последовательность **этапов**, которую вы сами настраиваете:

* 🔢 **сколько этапов будет** — вы сами добавляете/удаляете (хоть 1, хоть 20);
* ⏱ **задержка** — через сколько секунд после предыдущего сообщения бота отправить следующий;
* 📄 **тип контента** — текстовое сообщение / ссылка на файл с диска / ник в Telegram;
* 🔁 порядок этапов — меняете кнопками, этапы можно включать и выключать.

Управлять ботом можно **двумя способами** (оба ведут в одни и те же настройки):
* 🌐 **Веб-панель в браузере** — `http://<ваш_сервер>:8080`. Работает отовсюду,
  **не требует VPN и доступа к Telegram** (это просто HTTP-страница).
* 💬 **Команды в Telegram** — `/admin` и дальше кнопки (когда до Telegram есть доступ).

Типовой сценарий: приветственное сообщение → ссылка на скачивание файла
(Яндекс.Диск / Google Drive / MEGA) → ваш ник в Telegram.

## Возможности

### Клиентская панель (что видит клиент)
| Действие | Результат |
|---|---|
| Клиент нажимает **/start** (в т.ч. по ссылке `t.me/ваш_бот?start=...`) | Бот запускает последовательность: приветствие, затем с заданными задержками — ссылка на файл, ник и т.д. |
| Кнопка **«📥 Получить снова»** (после окончания) | Повторная отправка всей последовательности |
| Повторный /start | Последовательность перезапускается заново |
| Любое другое сообщение | Подсказка «нажмите /start» |

### 🌐 Веб-панель (главная, в браузере)
Открывается по адресу `http://<IP сервера>:8080` (пароль — `ADMIN_PASSWORD` в `.env`).

* список этапов: **✏️ редактировать, ⬆️/⬇️ порядок, 🔁 вкл/выкл, 🗑 удалить**;
* форма «Добавить этап»: **задержка → тип (📄 текст / 🔗 ссылка / 👤 ник) → контент**;
* **🧪 Тест сценария** — отправить все этапы в указанный чат: сразу или с реальными задержками;
* статус: имя бота, число этапов, аптайм;
* изменения сохраняются **мгновенно** и сразу действуют для новых клиентов (без перезапуска бота).

### 💬 Админ-команды в Telegram (тот же функционал, в чате с ботом)
| Команда | Что делает |
|---|---|
| `/admin` | Меню панели (кнопки) |
| `/add` | Мастер: **задержка → тип контента → контент** |
| `/stages` | Список этапов с кнопками управления |
| `/edit <N>` | Редактировать этап N (мастер, подставляет текущие значения) |
| `/del <N>` | Удалить этап |
| `/up <N>` / `/down <N>` | Поднять / опустить (изменить порядок) |
| `/on <N>` / `/off <N>` | Включить / выключить этап |
| `/test` | Прогнать сценарий **сразу** (без задержек) — проверить все этапы |
| `/test_live` | Прогнать сценарий **с реальными задержками** — как увидит клиент |
| `/cancel` | Отменить текущий мастер |

Доступ к Telegram-панели:
* укажите свой ID в `ADMIN_ID` в `.env` (узнать ID: напишите боту @userinfobot);
* можно несколько ID через запятую;
* если `ADMIN_ID` оставить пустым — **первый**, кто пришлёт боту `/admin`,
  станет админом (панель закроется для других).

Типы контента этапа:
* **📄 Текстовое сообщение** — приветствие, инструкции, любой текст (многострочный).
* **🔗 Ссылка на файл** — обычная ссылка на диск (Яндекс, Google, MEGA…) уходит
  сообщением с кликабельной ссылкой. Если ссылка ведёт **прямо на файл**
  (`.pdf`, `.zip`, `.mp4` …) — бот отправит его **как вложение**.
  Если Telegram не смог скачать файл по ссылке — автоматически отправит просто ссылку.
* **👤 Ник в Telegram** — превращается в кликабельную ссылку `t.me/ник`.

Доступ к панели:
* укажите свой ID в `ADMIN_ID` в `.env` (узнать ID: напишите боту @userinfobot);
* можно несколько ID через запятую;
* если `ADMIN_ID` оставить пустым — **первый**, кто пришлёт боту `/admin`,
  станет админом (панель закроется для других).

## Быстрый старт (5 минут)

### 1. Создайте бота и получите токен
1. В Telegram откройте **@BotFather** → `/newbot` → имя → короткий username.
2. BotFather выдаст **токен** вида `1234567890:AAEhB...` — это и есть «API ключ бота».
3. Узнайте свой числовой ID: напишите боту **@userinfobot**.

### 2. Подготовьте конфиг
```bash
cd telegram-bot
cp .env.example .env
```
Впишите в `.env`:
```env
BOT_TOKEN=1234567890:AAEhB...
ADMIN_ID=ваш_числовой_id
ADMIN_PASSWORD=пароль_для_веб_панели
```
(`ADMIN_PASSWORD` можно оставить пустым — тогда при первом запуске пароль
сгенерируется сам: он будет в логе и в файле `bot_data/admin_password.txt`.)

### 3. Запустите

**Самый простой способ — один скрипт** (сам создаст окружение, поставит
зависимости, создаст `.env` и запустит бота):

```bash
# Linux / macOS
./run.sh

# Windows
run.bat
```
Первый запуск попросит вписать токен в `.env` — впишите и запустите скрипт ещё раз.

**Вариант A — Docker (рекомендуется для сервера/24-7):**
```bash
docker compose up -d --build
```
Логи: `docker compose logs -f`
Обновление после правок: `docker compose up -d --build`

**Вариант B — Python 3.10+ (вручную):**
```bash
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
python main.py
```

### 4. Настройте этапы
Откройте в браузере **веб-панель** (пароль из `ADMIN_PASSWORD`):
* на той же машине, где запущен бот: `http://localhost:8080`
* с другой машины: `http://IP_вашей_машины_или_сервера:8080`

1. **➕ Добавить этап**: задержка (для приветствия — `0`), тип 📄, текст приветствия.
2. Добавьте второй этап: задержка `0` (или 2–5), тип **🔗 Ссылка на файл**,
   ссылка с вашего диска.
3. При необходимости — третий: **👤 Ник** (`@ваш_ник`).
4. Проверьте: **🧪 Тест сейчас** (введите свой чат-ID) и/или **▶️ Тест с реальными задержками**.
5. Отправьте бота клиенту — после /start он получит вашу последовательность.

То же самое можно делать командами в Telegram (`/admin`) — когда есть доступ к Telegram.

> При первом запуске бот сам создаёт `bot_data/stages.json` с двумя
> «демо-этапами» (приветствие + заглушка ссылки) — просто отредактируйте
> ссылку в этапе 2 кнопкой ✏️.

## 🇷🇺 Как запустить в России без замкнутого круга с VPN

Суть проблемы: боту нужен постоянный доступ к `api.telegram.org`, а в России
он заблокирован. Замкнутый круг: «VPN нужен для Telegram, но при VPN соединение
падает, а без VPN — заблокировано». Решение: **разделить**:

```
[Ваш компьютер в РФ]                [VPS в Европе / любой сервер без блокировок]
   браузер ──── http ──────────────►  бот (run.bat / docker)
   (настройка в веб-панели)          └──► polling Telegram (прямо, без VPN)
```

1. **Арендуйте VPS** в Европе (Netherlands/Germany и т.п.) — любой:
   Hetzner, DigitalOcean, Timeweb (EU) и т.п. — достаточно 1 vCPU и 512 МБ RAM.
2. Скопируйте папку `telegram-bot` на сервер (scp/git).
3. Заполните `.env` (токен, пароль) и запустите:
   ```bash
   docker compose up -d --build     # или ./run.sh
   ```
   Бот на сервере ходит в Telegram **прямо, без VPN** — там нет блокировок.
4. Настройте бота из **веб-панели** в браузере: `http://IP_вашего_VPS:8080`.
   Это обычная HTTP-страница — из России открывается **без VPN** (откройте
   порт 8080 в файрволе VPS, например: `sudo ufw allow 8080/tcp`).
5. Готово: бот работает 24/7 на сервере, вы настраиваете его из браузера,
   клиенты получают этапы в Telegram.

Логи сервера: `docker compose logs -f` или файл `bot_data/bot.log`.

## Структура проекта

```
telegram-bot/
├── main.py               # точка входа: бот (polling) + веб-сервер в одном процессе
├── config.py             # чтение .env (BOT_TOKEN, ADMIN_ID, WEB_PORT, ADMIN_PASSWORD, DATA_DIR)
├── storage.py            # этапы: модель Stage + JSON-хранилище (stages.json)
├── sender.py             # отправка этапа; фоновый проигрыватель (StageSequencer); тест
├── services.py           # логика доступа к админ-панели
├── web_panel.py          # веб-панель (FastAPI): API + логин
├── static/
│   └── index.html        # страница веб-панели
├── handlers/
│   ├── client.py         # клиентская панель (/start, «Получить снова»)
│   └── admin.py          # админ-команды в Telegram
├── tests/
│   ├── smoke_test.py        # офлайн-тесты логики: python tests/smoke_test.py
│   ├── integration_test.py  # тест через настоящий Dispatcher: python tests/integration_test.py
│   └── web_test.py          # тесты веб-панели: python tests/web_test.py
├── run.sh                # запуск одной командой (Linux/macOS)
├── run.bat               # запуск одной командой (Windows)
├── requirements.txt
├── .env.example          # шаблон конфига (скопируйте в .env)
├── Dockerfile
├── docker-compose.yml    # публикует порт веб-панели (WEB_PORT)
└── .dockerignore
```

Данные (ваши настроенные этапы) лежат в **`bot_data/stages.json`**
(путь можно поменять через `DATA_DIR`). В Docker каталог смонтирован на
`./bot_data`, поэтому этапы не потеряются при пересборке образа.

## Как устроена отправка

* После `/start` для клиента создаётся фоновая задача: для каждого включённого
  этапа — `await sleep(delay)` (задержка после **предыдущего** сообщения бота)
  и отправка. Задача живёт, пока бот запущен; повторный `/start` перезапускает
  последовательность, «Получить снова» — тоже.
* Ссылки на общие страницы дисков (Яндекс, Google, MEGA) отправляются текстом —
  Telegram не встраивает превью сторонних дисков, у клиента будет
  кликабельная ссылка. Чтобы файл шёл **вложением**, нужен прямой URL на файл
  (завершающийся расширением) — тогда бот отдаст его как документ.
* Этапы с `enabled = false` пропускаются. Задержки считаются в секундах
  (максимум — сутки).

## Остановка и обслуживание

```bash
# Docker
docker compose down          # остановить
docker compose up -d --build # обновить и запустить

# Локально
Ctrl+C в терминале
```

### Запуск 24/7 на Linux-сервере (systemd)

Создайте `/etc/systemd/system/tg-stage-bot.service`:
```ini
[Unit]
Description=Telegram stage bot
After=network-online.target

[Service]
WorkingDirectory=/путь/к/telegram-bot
ExecStart=/путь/к/telegram-bot/venv/bin/python main.py
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```
Далее:
```bash
sudo systemctl daemon-reload
sudo systemctl enable --now tg-stage-bot
journalctl -u tg-stage-bot -f   # логи
```

## Частые вопросы

**Клиент перестал получать этапы, бот переехал на другой сервер.**
Этапы — это файл `bot_data/stages.json`; скопируйте его (или пересоздайте
этапы через панель). Невысланные задержки «доживают» только пока бот работает.

**Как поменять приветствие?**
`/admin` → **📋 Список этапов** → кнопка ✏️ у этапа 1 → мастер (задержка/тип/текст).

**Могу ли я поставить один и тот же контент в нескольких этапах?**
Да — этапов может быть сколько угодно, порядок задаёте кнопками ⬆️/⬇️.

**Бот не запускается: «BOT_TOKEN не задан».**
Проверьте, что файл `.env` лежит рядом с `main.py` (или в корне папки
`telegram-bot` при Docker), токен вставлен целиком и без пробелов.

**Доступ к панели «⛔ Доступ запрещён».**
Проверьте `ADMIN_ID` в `.env` — это ваш числовой ID (узнать: @userinfobot),
после правки перезапустите бота.

## Тесты

```bash
pip install -r requirements.txt
python tests/smoke_test.py         # хранилище, отправка, секуэнсер, мастер
python tests/integration_test.py   # полное прохождение /start и /admin через aiogram
python tests/web_test.py           # веб-панель: логин, CRUD этапов, тест-отправка
```
Все тесты работают офлайн (без токена и без сети).

**Веб-панель не открывается с другой машины.**
Проверьте, что бот запущен, порт совпадает (`WEB_PORT`), и порт открыт в
файрволе сервера: `sudo ufw allow 8080/tcp` (для Docker — `ports` в compose).
С той же машины проверьте `http://localhost:8080`.

**Забыл пароль веб-панели.**
Либо задайте новый: `ADMIN_PASSWORD=новый_пароль` в `.env` + перезапуск.
Либо удалите файл `bot_data/admin_password.txt` — при следующем входе
сгенерируется новый (он покажется в логе).

**«Сеть недоступна — бот ЖИВ, переподключение…».**
Сервер бота не может достучаться до api.telegram.org (VPN/антивирус/сеть).
Бот не падает — ждёт и переподключится сам. На VPS в Европе VPN не нужен.

## Безопасность

* `.env` (токен) и `bot_data/` исключены из git (`.gitignore`) и из Docker-образа (`.dockerignore`).
* **Веб-панель защищена паролем** (`ADMIN_PASSWORD` в `.env` или сгенерированный
  пароль). Если бот стоит на публичном IP — пароль обязателен; при желании
  закройте порт 8080 файрволем и ходите через SSH-туннель:
  `ssh -L 8080:localhost:8080 user@ваш_vps`, затем `http://localhost:8080`.
* Telegram-админ-команды работают только в **личном чате** и только для ID
  из `ADMIN_ID` (либо для первого админа, пока ID не заданы).
* Токен — секрет: не публикуйте его, при утечке сразу `/revoke` у @BotFather.
