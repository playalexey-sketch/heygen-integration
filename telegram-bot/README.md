# 🤖 Telegram-бот с настройкой этапов (веб-панель + Telegram-панель)

Бот для «прогрева» клиентов: после нажатия **/start** он по очереди отправляет
клиенту последовательность **этапов**, которую вы сами настраиваете:

* 🔢 **сколько этапов будет** — вы сами добавляете/удаляете (хоть 1, хоть 20);
* ⏱ **задержка** — через сколько секунд после предыдущего сообщения бота отправить следующий;
* 📄 **тип контента** — текстовое сообщение / ссылка на файл с диска / ник в Telegram /
  **медиа-файл** (видео, аудио, картинка, документ — любого формата);
* 🔁 порядок этапов — меняете кнопками, этапы можно включать и выключать;
* 🔑 **ключевые слова / коды входа** — бот «слушает вход»: если клиент пришёл
  по ссылке `t.me/бот?start=КОД` или ввёл определённое слово, бот автоматически
  отправляет привязанный к нему контент (текст/ссылку/ник/медиа);
* 🌐 **ссылки для соцсетей** — для каждого кода бот сам генерирует ссылку
  `t.me/ваш_бот?start=КОД`; есть готовые для youtube / vk / instagram / tiktok
  (вставляете в описание видео, пост или шапку профиля);
* 👥 **CRM** — все клиенты автоматически собираются в базу: ID, ник,
  **откуда пришли** (код из ссылки), когда заходили, теги;
* ✉️ **выборочные рассылки** — всем клиентам / по тегу / по источнику
  (например, всем, кто пришёл с youtube);
* 💬 **переписка с клиентами** — каждое сообщение клиента приходит вам
  пересылкой в чат с ботом; отвечаете от имени бота (цитируя сообщение),
  вся переписка сохраняется и видна в вебе (вкладка «Чаты», там же можно
  писать клиенту).

Бот устроен как **два отдельных процесса**:
1. **`bot.py`** — сам Telegram-бот: polling, отправка этапов клиентам после /start.
   Работает только там, где есть доступ к Telegram. Лог: `bot_data/bot.log`.
2. **`admin.py`** — веб-админ-панель: настройка этапов в браузере.
   **Не требует доступа к Telegram** — работает даже когда бот «висит» на ретраях.
   Лог: `bot_data/admin.log`.

Процессы связаны общим файлом `bot_data/stages.json`: вы меняете этапы в
админке — бот перечитывает файл перед отправкой **каждому** клиенту,
поэтому изменения действуют мгновенно, без перезапуска.

Управлять этапами можно **двумя способами** (оба ведут в одни и те же настройки):
* 🌐 **Веб-панель в браузере** — `http://<ваш_сервер>:8080`. Работает отовсюду,
  **не требует VPN и доступа к Telegram** (это просто HTTP-страница).
* 💬 **Команды в Telegram** — `/admin` и дальше кнопки (когда до Telegram есть доступ).

Типовой сценарий: приветственное сообщение → ссылка на скачивание файла
(Яндекс.Диск / Google Drive / MEGA) → ваш ник в Telegram.

## Возможности

### Клиентская панель (что видит клиент)
| Действие | Результат |
|---|---|
| Клиент нажимает **/start** (в т.ч. по ссылке `t.me/ваш_бот?start=...`) | Бот запускает последовательность: приветствие, затем с заданными задержками — ссылка на файл, медиа, ник и т.д. |
| Клиент пришёл по ссылке **`t.me/ваш_бот?start=КОД`** | Помимо этапов, бот проверяет КОД по закладке «Ключевые слова» и автоматически отправляет привязанный контент |
| Клиент **ввёл слово/символ/цифру** | То же: если совпало с ключевым словом — бот шлёт привязанный контент |
| Кнопка **«📥 Получить снова»** (после окончания) | Повторная отправка всей последовательности |
| Повторный /start | Последовательность перезапускается заново |
| Неизвестное сообщение | Подсказка «нажмите /start» |

### 🔑 Как устроены «ключевые слова» (вкладка в веб-панели)

* **Триггер** — слово, символ, код или цифра (например `123`, `#promo`, `video`).
* **Режим**: «точное совпадение» (вход == триггер) или «содержит» (вход содержит триггер).
* **Контент** — что отправить: текст / ссылка / ник / медиа-файл.
* Бот показывает для каждого правила **готовую ссылку для клиента**:
  `https://t.me/имя_вашего_бота?start=триггер` (кнопка 📋 копирует её).
  Раздавайте разные ссылки разным группам клиентов — каждому придёт своё.
* Вход считывается два способа: код из ссылки `?start=...` (при /start)
  и любой текст, который клиент ввёл в чат с ботом.

### 💬 Как разведены админка и клиентская часть

* **Клиент** видит только сценарий: этапы после /start, кнопку
  «Получить снова», подсказки. Он не видит никаких админских команд.
* **Ваше (админское) пространство** — чат с ботом + веб-панель:
  1. Клиент пишет боту (текст/фото/видео/файл) → вы **сразу видите это
     пересылкой в своём чате с ботом** (с именем клиента).
  2. **Ответ от имени бота**: нажмите на сообщение клиента «Ответить» (⇱,
     цитата) и напишите текст — бот отправит его клиенту. Ответ файлом —
     тоже (отправьте файл, цитируя сообщение клиента).
  3. Та же переписка в вебе — вкладка **«💬 Чаты»**: история и поле ответа
     (клиент получит сообщение от бота).
  4. Вся история сохраняется (`bot_data/chats.json`), команды `/chats`
     и `/chat ID` — история в самом боте.
* Клиенты «слышат» только бота; вы «слышите» всех клиентов. Пересечение
  управляющих команд и клиентского сценария отсутствует.

### 🌐 Ссылки для соцсетей (YouTube / VK / Instagram / TikTok)

Бот **не подключается к аккаунтам соцсетей** (это запрещено правилами платформ
и небезопасно: риск бана аккаунта и кражи паролей). Вместо этого — рабочий и
надёжный механизм «воронки»:

1. `/rules` в Telegram показывает готовые ссылки для каждой соцсети:
   `https://t.me/ваш_бот?start=youtube`, `…?start=vk`, `…?start=instagram`,
   `…?start=tiktok` (и любую свою: код = триггер правила).
2. Вы вставляете нужную ссылку в **описание видео на YouTube, пост во VK,
   шапку профиля в Instagram/TikTok** — туда, откуда ведёте людей.
3. Клиент нажал ссылку → открылся **ваш бот в Telegram** → получил этапы
   и контент по коду → и **автоматически записан в CRM с меткой «из youtube»
   / «из vk» и т.д.**
4. Дальше с группами из каждой соцсети работаете рассылками:
   `/mail src:youtube …`, `/mail src:vk …` и т.д.

### 🌐 Веб-панель (главная, в браузере)
Открывается по адресу `http://<IP сервера>:8080` (пароль — `ADMIN_PASSWORD` в `.env`).
Вкладки:

* **📋 Этапы** — список (✏️ ️ ⬇️  вкл/выкл, 🗑 удалить), форма «Добавить этап»:
  задержка → тип (📄 текст / 🔗 ссылка / 👤 ник / 🎬 медиа-файл) → контент;
  плюс **🧪 Тест сценария** в указанный чат (сразу или с реальными задержками);
* **🎬 Медиа** — загрузка видео/аудио/картинок/документов любого формата
  (до 50 МБ — лимит Telegram-бота); файлы используются в этапах и правилах;
* **🔑 Ключевые слова** — правила «триггер → контент», режим совпадения,
  готовые ссылки `t.me/бот?start=триггер` для клиентов;
* **💬 Чаты** — переписка с клиентами: список чатов, полная история
  (обновляется автоматически), и **поле «написать клиенту от имени бота»** —
  единственный раздел, где можно менять данные из веба (по вашей просьбе);
* сверху — **🔌 Подключение к Telegram** (прокси VPN, см. ниже) и статус
  (имя бота, число этапов/медиа/слов, клиентов, аптайм).

Изменения сохраняются **мгновенно** и сразу действуют для новых клиентов (без перезапуска бота).

### 💬 Управление — в Telegram (основной способ)
Все настройки делаются командами в личном чате с ботом. **Веб-панель —
только отображение** того, что задано в Telegram.

| Команда | Что делает |
|---|---|
| `/help` | **полный справочник всех команд** (для админа) |
| `/setmenu` | обновить меню «/» бота (подсказки при вводе «/») |
| `/admin` | Меню панели (кнопки) |
| `/add` | Мастер этапа: **задержка → тип контента → контент** (медиа — файлом) |
| `/stages` | Список этапов с кнопками управления |
| `/edit <N>`, `/del <N>`, `/up <N>`, `/down <N>`, `/on <N>`, `/off <N>` | управление этапами |
| `/test`, `/test_live` | прогнать сценарий сразу / с реальными задержками |
| `/rules` | **список правил и готовых ссылок** (в т.ч. для соцсетей) |
| `/addrule` | Мастер правила: триггер → режим → тип контента → контент |
| `/delrule <N>`, `/onrule <N>`, `/offrule <N>` | управление правилами |
| `/media`, `/upmedia` | список медиа-файлов / загрузить файл сообщением |
| `/proxy`, `/setproxy <url>` | текущий прокси / установить (VPN) |
| `/chats` | **чаты клиентов**: последние сообщения по каждому |
| `/chat ID` | последние сообщения с конкретным клиентом |
| `/crm` | **CRM**: клиенты, откуда пришли, теги |
| `/tag <ID> <тег>`, `/untag <ID> <тег>` | теги клиентов |
| `/mail all <текст>` | рассылка всем клиентам |
| `/mail tag:<тег> <текст>` | рассылка по тегу |
| `/mail src:<источник> <текст>` | рассылка по источнику (youtube, vk, …) |
| `/cancel` | отменить текущий мастер |

Доступ к Telegram-панели:
* укажите свой ID в `ADMIN_ID` в `.env` (узнать ID: напишите боту @userinfobot);
* можно несколько ID через запятую;
* если `ADMIN_ID` оставить пустым — **первый**, кто пришлёт боту `/admin`,
  станет админом (панель закроется для других).

Типы контента этапа:
* **📄 Текстовое сообщение** — приветствие, инструкции, любой текст (многострочный).
* **🔗 Ссылка на файл** — обычная ссылка на диск (Яндекс, Google, MEGA…) уходит
  сообщением с кликабельной ссылкой. Если ссылка ведёт **прямо на файл**
  (`.pdf`, `.zip`, `.mp4` …) — бот отправит его **как вложение**.
  Если Telegram не смог скачать файл по ссылке — автоматически отправит просто ссылку.
* **👤 Ник в Telegram** — превращается в кликабельную ссылку `t.me/ник`.

Доступ к панели:
* укажите свой ID в `ADMIN_ID` в `.env` (узнать ID: напишите боту @userinfobot);
* можно несколько ID через запятую;
* если `ADMIN_ID` оставить пустым — **первый**, кто пришлёт боту `/admin`,
  станет админом (панель закроется для других).

## Быстрый старт (5 минут)

### 1. Создайте бота и получите токен
1. В Telegram откройте **@BotFather** → `/newbot` → имя → короткий username.
2. BotFather выдаст **токен** вида `1234567890:AAEhB...` — это и есть «API ключ бота».
3. Узнайте свой числовой ID: напишите боту **@userinfobot**.

### 2. Подготовьте конфиг
```bash
cd telegram-bot
cp .env.example .env
```
Впишите в `.env`:
```env
BOT_TOKEN=1234567890:AAEhB...
ADMIN_ID=ваш_числовой_id
ADMIN_PASSWORD=пароль_для_веб_панели
```
(`ADMIN_PASSWORD` можно оставить пустым — тогда при первом запуске пароль
сгенерируется сам: он будет в логе и в файле `bot_data/admin_password.txt`.)

### 3. Запустите

**Самый простой способ — один скрипт** (сам создаст окружение, поставит
зависимости, создаст `.env` и запустит **оба процесса**: бот + веб-админка):

```bash
# Linux / macOS
./run.sh

# Windows
run.bat
```
Первый запуск попросит вписать токен в `.env` — впишите и запустите скрипт ещё раз.

Раздельный запуск процессов:
```bash
./run.sh bot     # только Telegram-бот          # Windows: run.bat bot
./run.sh admin   # только веб-админка           # Windows: run.bat admin
```

**Вариант A — Docker (рекомендуется для сервера/24-7):**
```bash
docker compose up -d --build
```
Логи: `docker compose logs -f`
Обновление после правок: `docker compose up -d --build`

**Вариант B — Python 3.10+ (вручную):**
```bash
python3 -m venv venv
source venv/bin/activate        # Windows: venv\Scripts\activate
pip install -r requirements.txt
python main.py
```

### 4. Настройте этапы
Откройте в браузере **веб-панель** (пароль из `ADMIN_PASSWORD`):
* на той же машине, где запущен бот: `http://localhost:8080`
* с другой машины: `http://IP_вашей_машины_или_сервера:8080`

1. **➕ Добавить этап**: задержка (для приветствия — `0`), тип 📄, текст приветствия.
2. Добавьте второй этап: задержка `0` (или 2–5), тип **🔗 Ссылка на файл**,
   ссылка с вашего диска.
3. При необходимости — третий: **👤 Ник** (`@ваш_ник`).
4. Проверьте: **🧪 Тест сейчас** (введите свой чат-ID) и/или **▶️ Тест с реальными задержками**.
5. Отправьте бота клиенту — после /start он получит вашу последовательность.

То же самое можно делать командами в Telegram (`/admin`) — когда есть доступ к Telegram.

> При первом запуске бот сам создаёт `bot_data/stages.json` с двумя
> «демо-этапами» (приветствие + заглушка ссылки) — просто отредактируйте
> ссылку в этапе 2 кнопкой ✏️.

## 🔑 Бот не подключается к Telegram: прокси вашего VPN

**Симптомы:** в окне бота повторяется `Сеть недоступна — бот ЖИВ, переподключение…`,
веб-панель при этом работает. В браузере Telegram Web через VPN открывается.

**Почему так:** VPN-клиенты на Windows часто работают как **системный прокси**:
браузеры ходят через него (поэтому веб-Telegram открывается), а Python-бот **не
видит** этот прокси и идёт напрямую — в блокировку.

**Решение — указать боту прокси вашего VPN. Порт смотрите в настройках клиента:**

| Клиент | Прокси |
|---|---|
| v2rayN | `socks5://127.0.0.1:10808` (SOCKS5-порт, по умолчанию 10808) |
| Clash / Clash Verge | `http://127.0.0.1:7890` (Mixed Port) |
| Shadowsocks (локальный клиент) | `socks5://127.0.0.1:1080` |
| другие | `socks5://127.0.0.1:<порт из настроек клиента>` |

**Как включить (без перезапуска):**
1. В веб-панели — карточка **«🔌 Подключение к Telegram (VPN / прокси)»**.
2. Введите адрес (например, `socks5://127.0.0.1:10808`).
3. Кнопка **«🔍 Просто попробовать»** — проверит, не сохраняя.
   Кнопка **«💾 Сохранить и проверить»** — сохранит и проверит.
   Результат сразу на экране: `Соединение установлено через … — бот @имя ✔`
   или честная ошибка (неверный порт, прокси не запущен, 401 и т.д.).
4. Бот подхватит сохранённый прокси **сам, без перезапуска** (~15 секунд).
   Проги живут в `bot_data/proxy.txt`.

Альтернатива без панели: `TELEGRAM_PROXY=socks5://127.0.0.1:10808` в `.env`
+ перезапуск процессов.

**Туннельный VPN (WireGuard / OpenVPN, «весь трафик через туннель»)?**
Прокси не нужен: включите VPN и проверьте
`Test-NetConnection api.telegram.org -Port 443`. Если `True` — бот подключится
сам (IPv4 принудительно). Если `False` при включённом VPN — у клиента включён
split tunneling: настройте маршрутизацию ВСЕГО трафика через туннель.

## 🇷 Как запустить в России без замкнутого круга с VPN

Суть проблемы: боту нужен постоянный доступ к `api.telegram.org`, а в России
он заблокирован. Замкнутый круг: «VPN нужен для Telegram, но при VPN соединение
падает, а без VPN — заблокировано». Решение: **разделить**:

```
[Ваш компьютер в РФ]                [VPS в Европе / любой сервер без блокировок]
   браузер ──── http ──────────────►  бот (run.bat / docker)
   (настройка в веб-панели)          └──► polling Telegram (прямо, без VPN)
```

1. **Арендуйте VPS** в Европе (Netherlands/Germany и т.п.) — любой:
   Hetzner, DigitalOcean, Timeweb (EU) и т.п. — достаточно 1 vCPU и 512 МБ RAM.
2. Скопируйте папку `telegram-bot` на сервер (scp/git).
3. Заполните `.env` (токен, пароль) и запустите:
   ```bash
   docker compose up -d --build     # или ./run.sh
   ```
   Бот на сервере ходит в Telegram **прямо, без VPN** — там нет блокировок.
4. Настройте бота из **веб-панели** в браузере: `http://IP_вашего_VPS:8080`.
   Это обычная HTTP-страница — из России открывается **без VPN** (откройте
   порт 8080 в файрволе VPS, например: `sudo ufw allow 8080/tcp`).
5. Готово: бот работает 24/7 на сервере, вы настраиваете его из браузера,
   клиенты получают этапы в Telegram.

Логи сервера: `docker compose logs -f` или файл `bot_data/bot.log`.

telegram-bot/
├── bot.py                # ПРОЦЕСС 1: Telegram-бот (polling, отправка этапов, ключевые слова)

├── app_common.py         # общее: конфиг, логи, IPv4-сессия, прокси, сборка объектов
├── config.py             # чтение .env (BOT_TOKEN, ADMIN_ID, WEB_PORT, ADMIN_PASSWORD, TELEGRAM_PROXY, DATA_DIR)
├── storage.py            # этапы: модель Stage + JSON-хранилище (stages.json, reload)
├── content.py            # медиа + правила «ключевое слово -> контент» (content.json + media/)

Данные (ваши настроенные этапы) лежат в **`bot_data/stages.json`**
(путь можно поменять через `DATA_DIR`). В Docker каталог смонтирован на
`./bot_data`, поэтому этапы не потеряются при пересборке образа.

## Как устроена отправка

* После `/start` для клиента создаётся фоновая задача: для каждого включённого
  этапа — `await sleep(delay)` (задержка после **предыдущего** сообщения бота)
  и отправка. Задача живёт, пока бот запущен; повторный `/start` перезапускает
  последовательность, «Получить снова» — тоже.
* Ссылки на общие страницы дисков (Яндекс, Google, MEGA) отправляются текстом —
  Telegram не встраивает превью сторонних дисков, у клиента будет
  кликабельная ссылка. Чтобы файл шёл **вложением**, нужен прямой URL на файл
  (завершающийся расширением) — тогда бот отдаст его как документ.
* Этапы с `enabled = false` пропускаются. Задержки считаются в секундах
  (максимум — сутки).

### Запуск 24/7 на Linux-сервере (systemd)

Создайте два сервиса (по одному на процесс). `/etc/systemd/system/tg-stage-bot.service`:
```ini
[Unit]
Description=Telegram stage bot
After=network-online.target

[Service]
WorkingDirectory=/путь/к/telegram-bot
ExecStart=/путь/к/telegram-bot/venv/bin/python bot.py
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```
`/etc/systemd/system/tg-stage-admin.service` — то же, но `ExecStart=.../python admin.py`
и `Description=Telegram stage bot web admin`.
Далее:
```bash
sudo systemctl daemon-reload
sudo systemctl enable --now tg-stage-bot tg-stage-admin
journalctl -u tg-stage-bot -f    # логи бота
```
(или проще — Docker: `docker compose up -d --build` поднимет оба сервиса сам.)

## Частые вопросы

**Клиент перестал получать этапы, бот переехал на другой сервер.**
Этапы — это файл `bot_data/stages.json`; скопируйте его (или пересоздайте
этапы через панель). Невысланные задержки «доживают» только пока бот работает.

**Как поменять приветствие?**
`/admin` → **📋 Список этапов** → кнопка ✏️ у этапа 1 → мастер (задержка/тип/текст).

**Могу ли я поставить один и тот же контент в нескольких этапах?**
Да — этапов может быть сколько угодно, порядок задаёте кнопками ⬆️/⬇️.

**Бот не запускается: «BOT_TOKEN не задан».**
Проверьте, что файл `.env` лежит в корне папки `telegram-bot` (рядом с
`bot.py`/`admin.py`; при Docker — в том же месте, что и `docker-compose.yml`),
токен вставлен целиком и без пробелов.

**CRM: клиенты из прошлой версии не потерялись?**
База клиентов (`bot_data/crm.json`) создаётся с этого обновления; все клиенты,
которые нажмут /start (или напишут что-либо) с этого момента, попадут в базу.
Чтобы полностью сбросить CRM — остановите бота и удалите файл
`bot_data/crm.json` (он пересоздастся).

**Как остановить каждый процесс?**
Windows: `Ctrl+C` в окне процесса (или закрыть окно). Linux: `Ctrl+C` в терминале;
если админка запущена в фоне — `pkill -f 'python admin.py'`. Docker:
`docker compose down`.

**Доступ к панели «⛔ Доступ запрещён».**
Проверьте `ADMIN_ID` в `.env` — это ваш числовой ID (узнать: @userinfobot),
после правки перезапустите бота.

## Тесты

```bash
pip install -r requirements.txt
python tests/smoke_test.py         # хранилище, отправка, секуэнсер, мастер
python tests/integration_test.py   # полное прохождение /start и /admin через aiogram
python tests/web_test.py           # веб-панель: логин, CRUD этапов, тест-отправка
```
Все тесты работают офлайн (без токена и без сети).

**Веб-панель не открывается с другой машины.**
Проверьте, что бот запущен, порт совпадает (`WEB_PORT`), и порт открыт в
файрволе сервера: `sudo ufw allow 8080/tcp` (для Docker — `ports` в compose).
С той же машины проверьте `http://localhost:8080`.

**Забыл пароль веб-панели.**
Либо задайте новый: `ADMIN_PASSWORD=новый_пароль` в `.env` + перезапуск.
Либо удалите файл `bot_data/admin_password.txt` — при следующем входе
сгенерируется новый (он покажется в логе).

**«Сеть недоступна — бот ЖИВ, переподключение…».**
Машина бота не может достучаться до api.telegram.org (блокировка).
Бот не падает — ждёт и переподключится сам. Лечение:
прокси VPN из веб-панели (раздел «🔌 Подключение к Telegram») или VPS в Европе.

## Безопасность

* `.env` (токен) и `bot_data/` исключены из git (`.gitignore`) и из Docker-образа (`.dockerignore`).
* **Веб-панель защищена паролем** (`ADMIN_PASSWORD` в `.env` или сгенерированный
  пароль). Если бот стоит на публичном IP — пароль обязателен; при желании
  закройте порт 8080 файрволем и ходите через SSH-туннель:
  `ssh -L 8080:localhost:8080 user@ваш_vps`, затем `http://localhost:8080`.
* Telegram-админ-команды работают только в **личном чате** и только для ID
  из `ADMIN_ID` (либо для первого админа, пока ID не заданы).
* Токен — секрет: не публикуйте его, при утечке сразу `/revoke` у @BotFather.
