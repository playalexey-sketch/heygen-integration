# Личный LLM — на твоём компе, веса живут на диске

Маленькая языковая модель (GPT) на **чистом Python + NumPy** — без PyTorch, без CUDA,
без GPU. Обучение и диалог идут на обычном ноутбуке.

Ключевое свойство (то, ради чего всё это): **в RAM загружается только то, что нужно
прямо сейчас, остальное лежит на диске**. Модель любого размера живёт в одном бинарном
файле; кэш в оперативной памяти ограничен (`--ram-mb`) и работает по LRU — слой, который
не нужен в данный момент, вытесняется обратно «на диск» (файл всё там же, читаем снова,
когда понадобится).

Архитектура модели — GPT-2, взята из открытого [nanoGPT](https://github.com/karpathy/nanoGPT)
(MIT). Всё, что здесь написано, — учебный код: медленнее, зато прозрачный и запускается
везде, где есть `python3` + `numpy`.

## Как это устроено

```
weights.bin  (на диске, источник правды)
   │  «прочитай слой i»
   ▼
OffloadCache — LRU-кэш в RAM (бюджет задаётся)
   │  tensor (B,C)
   ▼
вперёд / назад по токенам
```

* **weights.bin** — все веса модели в одном бинарном файле (float32 или int8).
* **OffloadCache** — кэш тензоров в RAM с бюджетом в мегабайтах. Запрос `get(name)`:
  есть в кэше → отдаём; нет → читаем с диска, ставим в кэш, при переполнении вытесняем
  самый давно не тронутый. Тренировка и инференс ходят в кэш послойно, поэтому в памяти
  одновременно живут только последние несколько слоёв (плюс KV-кэш и embedding).
* **История диалога** тоже на диске (`history.bin`): в контекст берутся только последние
  `block_size` токенов, всё остальное — в файле.
* Инференс — посимвольный декодинг с KV-кэшем (как в nanoGPT): каждый новый токен
  прогоняется только через «хвост», вычисления не повторяются. Проверено в тестах:
  посимвольный проход бит-в-бит совпадает с полным проходом.

Честно про скорость: на ноутбуке инференс — порядка 1–5 токенов/с (микро-модель),
обучение — десятки секунд на 15 000 токенов. Это про *принцип*, не про производительность.

## Установка

Нужен только Python 3.9+ и NumPy:

```bash
cd personal-llm
python3 -m pip install numpy
```

## Быстрый старт: обучи на своих записках

1. Собери свои тексты в один файл (заметки, переписки, черновики — что угодно,
   лучше 10–50+ КБ):

   ```bash
   cat заметки.txt письма.txt > my_corpus.txt
   ```

2. Обучи модель (1–3 минуты на ноутбуке):

   ```bash
   python3 llm.py train --data my_corpus.txt --name my
   ```

3. Поговори:

   ```bash
   python3 llm.py chat --model my
   ```

   Команды в чате: `/stats` — что в RAM, сколько прочитано с диска; `/reset` — чистый
   контекст; `/exit`.

Готовые примеры текстов лежат в `data_example/`.

## Все команды

```bash
python3 llm.py train --data my_corpus.txt --name my
    # --preset micro|small   размер (micro ~11 МБ, small ~54 МБ)
    # --tokens 60000         сколько токенов прогнать (эпох = tokens / len(corpus))
    # --quant                int8 на диске: 4 раза меньше файл
    # --vocab 512            размер словаря BPE
    # --data-dir DIR         где хранить модели (по умолчанию ~/.cache/personal-llm)

python3 llm.py chat --model my
    # --ram-mb 256           бюджет RAM (по умолчанию 25% памяти, 128–1024 МБ)
    # --show-offload         печатать каждое «с диска / вытеснен»
    # --temp 0.9 --top-k 40  параметры генерации
    # --max-new 128          длина ответа

python3 llm.py gen --model my --text "задачи:" --max-new 64 --no-history

python3 llm.py info --model my          # что за модель, где файл, сколько весит

python3 llm.py presets list             # открытые пресеты (нужен интернет)
python3 llm.py presets gpt2 --int8      # скачать GPT-2 124M (~550 МБ → ~140 МБ int8)
```

## Как посмотреть «подгрузку только нужного»

Сожмите бюджет RAM, чтобы увидеть механизм в работе:

```bash
python3 llm.py chat --model my --ram-mb 6 --show-offload
```

Будет видно:

```
[offload] + RAM  attn_0.wqkv   0.4 МБ (с диска)
[offload] + RAM  mlp_3.w1      0.6 МБ (с диска)
[offload] - RAM  wte           0.3 МБ (вытеснен, остался на диске)
...
```

Модель целиком на диске, в памяти — 6 МБ, и она продолжает работать. `/stats` покажет
итог: попадания/промахи кэша, вытеснения, сколько всего прочитано с диска.

## Честные ограничения

* **Качество текста**: микро-модель (11 МБ) на 2–10 КБ текста выдаёт «стиль», а не смысл —
  это нормально для модели такого размера. Чем больше корпус (стопы слов), тем лучше.
* **Скорость**: NumPy — это медленно. 150M+ на ноутбуке без GPU не потянуть.
* **GPT-2**: нужен интернет при скачивании (~550 МБ), английский язык, ~2–5 ток/с.
* **int8**: квантизация по 1 байту на вес, точность чуть ниже float32 (видно на loss,
  на тексте почти не заметно).
